**阶段**: v2.1 | **分类**: bugfix | **类型**: bugfix | **主题**: rdd-quick mode a 半正式中间态边界修复

## Why

2026-09-28 双 Agent 审查（oracle 高 IQ 推理 + Metis 元评估）暴露 rdd-quick mode a 路径三个未验证边界：

### 边界 1（oracle 标 P1）: mode a archive gate 兼容性

rdd-quick mode a（从 `rdd-builder P0` 选项 5 dispatch-quick 进入）完成后调用 `openspec archive <change> --yes`，但 rdd-quick 硬约束**禁止写 `openspec/changes/<name>/tasks.md`**。`archive_gate_check`（per AGENTS.md "Guide-Ship 执行契约"）检查 tasks.md 完成度作为 archive 前置 gate。

**后果**：mode a 成功路径上 `archive_gate_check` 行为**未定义 + 未测试**——tasks.md 缺失时 gate 可能阻断 archive，或静默放过导致后续 rdd-verifier 无 AC 可读。

### 边界 2（Metis 标"比 Sisyphus 8 个问题更危险"）: rdd-verifier 兼容性

rdd-verifier SKILL.md Step 1 AC 提取规则：读 `openspec/changes/<name>/proposal.md::## 验收标准` 段。rdd-quick mode a 的 AC **不在 proposal.md**（在 `.rddf/plans/quick-<name>.md::## Acceptance`）。

**后果**：
- archive 落 `openspec/changes/archive/` 后 rdd-verifier 触发时找不到 AC → 验证 fail → 误报
- 或 verifier 直接跳过 archive change → 用户以为已验证实则无验证 → false sense of security

### 边界 3（oracle 标 P2）: `rdd-quick-context.json` 无 cleanup 契约

`rdd-quick/SKILL.md` L28 frontmatter `owns` 标 `.rddf/state/rdd-quick-context.json (临时, per ADR-0048)` 但**无清理契约**：
- mode a 完成 → context 残留 → 下次 mode a 读到 stale advisory
- mode a escalated → context 残留 → 下次 mode a 用错 change_name

### 根因（oracle）

ADR-0048 §Decision 3 amendment 把"已有 openspec change 半成品"嫁接进一个原本只为"零 change"设计的 skill（ADR-0047），mode a 的 archive / git / cleanup 语义是后补散文、未经 gate 级验证。所有真问题都是这个"半正式中间态"的边界表现。

## What Changes

### Fix 1: mode a archive 前生成最小 tasks.md

**新文件**: `skills/rdd-quick/scripts/generate_tasks_md.py`（≤80 LOC, stdlib only）

**契约**：
- 输入: `--change <name> --plan <path/to/quick-<name>.md> --proposal <path/to/proposal.md>`
- 读取 plan 的每个 `### Task N` 标题 + 5 个 TDD step marker，生成最小 tasks.md：
  ```markdown
  ## 1. Setup
  - [x] 1.1 Read proposal.md and confirm scope (via rdd-quick mode a)
  
  ## 2. Implementation
  - [x] 2.1 <Task 1 title>
  - [x] 2.2 <Task 2 title>
  - [x] 2.3 <Task N title>
  
  ## 3. Verification
  - [x] 3.1 Run `openspec validate <change>` (passed via mode a AC verification)
  - [x] 3.2 rdd-verifier compatibility: AC synced to proposal.md (per Fix 2)
  ```
- 仅在 `openspec/changes/<change>/tasks.md` 不存在时生成；存在则跳过（idempotency）
- 写后输出 stdout 一行 `<tasks_md_path>`

**SKILL.md 变更**（L96-100 段）：
- mode a 完成分支新增 Step：调用 `generate_tasks_md.py` 生成最小 tasks.md
- 在 `## Permission Context` 部分标注"mode a 隐式授权写 tasks.md（最小化、非逐任务回写）"
- 在 frontmatter `owns` 新增 `openspec/changes/<change>/tasks.md (mode a 最小化生成, per ADR-0048 amendment)`

### Fix 2: mode a 完成时同步 AC 到 proposal.md

**新文件**: `skills/rdd-quick/scripts/sync_ac_to_proposal.py`（≤60 LOC, stdlib only）

**契约**：
- 输入: `--plan <path/to/quick-<name>.md> --proposal <path/to/proposal.md>`
- 解析 plan 的 `## Acceptance` 段（checkbox `- [ ] **AC-N** description`）
- 在 proposal.md 末尾追加 `## Acceptance (from rdd-quick plan)` 段（若不存在）：
  ```markdown
  ## Acceptance (from rdd-quick plan)
  
  Source: .rddf/plans/quick-<name>.md::## Acceptance
  Generated: <ISO8601 timestamp>
  
  <!-- BEGIN rdd-quick-ac -->
  - [ ] **AC-1** <verbatim from plan>
  - [ ] **AC-2** <verbatim from plan>
  <!-- END rdd-quick-ac -->
  ```
- Idempotency: 检测 `<!-- BEGIN rdd-quick-ac -->` 标记，更新而非重复追加
- 写后输出 stdout 一行 `<count> ACs synced`

**SKILL.md 变更**（mode a 流程新增 Step）：
- 调用 `sync_ac_to_proposal.py` 在 Fix 1 后、archive 前
- `## Permission Context` 标注"mode a 隐式授权追加 AC 段到 proposal.md（仅追加 `## Acceptance (from rdd-quick plan)` 子段）"

### Fix 3: `rdd-quick-context.json` cleanup hook

**新文件**: `skills/rdd-quick/scripts/cleanup_context.sh`（≤40 LOC）

**契约**：
- 输入: `--reason completed|escalated`
- 调用时机：
  - mode a `outcome=completed` 写 audit log 之后
  - mode b `outcome=completed` 写 audit log 之后
  - mode a/b `outcome=escalated` 写 audit log 之后
- 操作：
  1. `rm -f .rddf/state/rdd-quick-context.json`（若存在）
  2. 写一条 cleanup trace 到 `.rddf/state/.quick-history.jsonl`：
     ```json
     {"event": "context_cleanup", "reason": "<reason>", "deleted_at": "<ISO8601>"}
     ```
- 不存在 → 静默退出 0

**SKILL.md 变更**：
- mode a/b 完成的 P4 段、escalated 段都新增 cleanup Step
- frontmatter `owns` 移除"（临时）"标记 → 改为"owned lifecycle: created in P0, deleted in P4"

## Acceptance

> 5 个 AC（按 rdd-verifier VERDICT_ITEM_SCHEMA 输出，机器可验证）

- [ ] **AC-1**: `generate_tasks_md.py` 在 plan 含 3 个 Task 时生成的 tasks.md 含 1 个 Setup 项 + 3 个 Implementation 项 + 2 个 Verification 项（per Setup/Implementation/Verification 三段固定结构），tasks.md 不存在时生成，已存在时跳过
- [ ] **AC-2**: `sync_ac_to_proposal.py` 解析 plan 的 `## Acceptance` 段后，proposal.md 末尾追加含 `<!-- BEGIN rdd-quick-ac -->` / `<!-- END rdd-quick-ac -->` 标记的 AC 段，二次调用 idempotent（不重复追加）
- [ ] **AC-3**: `cleanup_context.sh` 存在 `.rddf/state/rdd-quick-context.json` 时删除并写 audit log 条目，不存在时退出码 0 且无副作用
- [ ] **AC-4**: `skills/rdd-quick/SKILL.md` 在 mode a 流程段（P4 completion）新增对 3 个新脚本的调用指令，且 frontmatter `owns` 列表更新（移除"（临时）"标记）
- [ ] **AC-5**: 新增 3 个 bats 测试 + 1 个 pytest 测试，CI 配置 `./test.sh --full --regression` 全绿，无新增失败（基于 KNOWN_FAILURES.txt baseline 对比）

## Capabilities

### MUST

- rdd-quick mode a 完成后 archive gate (`archive_gate_check`) 必须能正常通过（tasks.md 最小化生成 + AC 同步双保险）
- rdd-verifier 在 archive 后必须能正确读到 AC（从 proposal.md 末尾 `## Acceptance (from rdd-quick plan)` 段提取）
- rdd-quick-context.json 在 P4 完成/escalated 后必须被清理（避免 stale advisory）

### MUST NOT

- 不创建 `openspec/changes/<change>/design.md`（rdd-quick 不产出）
- 不创建 `openspec/specs/<change>/spec.md`（rdd-quick 不产出）
- 不创建 `.rddf/wt/<change>/`（rdd-quick 禁止 worktree）
- 不创建 `openspec/changes/archive/<change>/`（archive 由 mode a 自动触发，不属于 rdd-quick 责任）
- 不读 rdd-builder 保留 env vars（`QUICK_FINISH_DETECTED`, `SKIP_PROMETHEUS_PLANNING`，per frontmatter `forbidden_env_vars`）
