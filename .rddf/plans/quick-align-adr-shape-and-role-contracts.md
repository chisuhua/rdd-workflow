# quick-align-adr-shape-and-role-contracts

> **Generated by rdd-quick scaffold_plan.sh** — 本文件已按 rdd-quick P0 要求填实。
> 复杂度分流：complex（Metis + Oracle 双审通过，用户已确认三项处置）。

**Goal**: 让 rdd-workflow 的 **ADR 形态契约**在「散文契约（模板 + opencode build.md）」与「机械门禁（`_check_adr_shape`）」之间对齐，并让 rdd-workflow 侧的**角色边界事实**与 opencode build agent 的角色矩阵保持一致。

具体：
1. **P0-3** `_DEFAULT_ADR_LINE_LIMIT` 300 → 250（让机械门与模板/build.md 的 250 同源）。
2. **P0-4** 扩 `_check_adr_shape()`：加「Verification 章节存在」检查；加「备选方案表 ≥3 数据行且含『结论』列」检查（三条独立 issue：缺表 / 行数不足 / 缺结论列）；把 `_PROCESS_LOG_PATTERNS` 扩到能命中本仓真实漂移形态（锚定 heading、去产品名、拆「过程/版本史」与「越界成 how-to」两类）。
3. **P0-4 附带** 消除 `adr_shape_check.sh` 的内联双写：把 findings 提升为一级 API（`adr_shape_findings()`），gate 与 CLI 共用；findings 结构化（signal/file/detail）并进 `ArchQualityReport.detail`；顺手修 `--strict` 死参数。
4. **P1-4** `.rddf/` 布局清单：`state` 条目 `write_by` 由 `("rdd",)` 改 `("rdd","agent")`（`.rddf/state/role.json` 由 agent 写）；`docs/architecture/rddf-layout.md` 新增「治理状态」子表（`role.json` / `pair.json` / `.rddf/reviews/*.md`）。
5. **P1-2 / P1-3（经用户确认后重定向）** **不改** `role.boundaries.owns`（违反 `openspec/specs/skill-role-model/spec.md` 的 owns-generated-artifacts-only，且破坏 `state_paths.py` 逐字节不变量）。改为按 design.md 先例，在 **SKILL.md 正文**加作者声明：`.rddf/reviews/**` 与 `arch-docs.json` 属 opencode 角色层写集，非本 skill 产物。概念分层由 Phase 3 的 `docs/architecture/agent-role-alignment.md` 承载。

**Architecture**:
`_lib/arch_quality_gate.py` 是形态判定的**唯一真源**。新增 `adr_shape_findings(ctx) -> list[Finding]` 作为一级 API，逐文件产出结构化 findings（signal / file / detail）；`_check_adr_shape(ctx)` 委托它并保持 `(bool, Optional[str])` 签名不变（`ArchQualityReport.verify()` 与既有单测调用面不变），同时把 findings 写进 `report.detail[name]`。`skills/rdd-arch/scripts/adr_shape_check.sh` 改为 import 该 API 打印 findings，删除内联判定循环与硬编码的 `300` / `200` 默认值（改为 import `_DEFAULT_ADR_LINE_LIMIT` / `_DEFAULT_ADR_STATUS_MAX`）。扫描范围默认**增量**（`ctx["adr_files"]`，即本轮新写/改动的 ADR），全量走显式 `--all`，复现 ADR-0060「存量不追溯」的原意并避免 55/60 的存量债淹没真实新增问题。

**Tech Stack**: Python 3.11+（stdlib only，无新依赖）、bash 4+、pytest、bats、JSON Schema（`skill_role_schema.json`）。

## Risks / Assumptions（Metis）

- **「行数」口径**：`_check_adr_shape` 按 `len(text.splitlines())` = **全文物理行数**（含标题、表格分隔行、空行）；模板 `:8` 说的是「**正文**目标 ≤ 250」且明确把推导/证据排除在正文外。本轮**不改计数口径**（会破坏既有「13 份超 300」基线），但在 docstring 写明「按全文物理行数计」，避免「对齐」是假的。
- **软约束 vs 硬上限**：模板措辞是「目标 ≤ 250」，机械门是硬判定。本轮只统一**数值**，不改措辞语义；措辞对齐留待 ADR-0060 修订时一并处理。
- **Verification 章节的双语层级陷阱**：`## 验证` 在 ADR-0018/0019 是**真**验收章；而 ADR-0050 的 `### 验证 ADR-0048 + ADR-0049 零 regression` 是散文子标题 ⇒ 必须限定 **h2** 层级 + 行尾锚定（可选尾随注记），否则假阴性放行。
- **备选表定位**：一个 ADR 常有 2 张表（影响范围表 + 备选表）⇒ 必须在 Alternatives 章节内、以下一个 `^#{2,4}` 为界截断，再取第一张表；「文件里第一张表」启发式必错。
- **备选表结论列的同义词**：中文可能是 结论/取舍/决定/裁决，英文可能是 Decision/Verdict/Accepted/Outcome/Conclusion ⇒ 用集合匹配，不硬匹配「结论」二字。
- **自指误伤**：ADR-0060 正文引用 `第 N 轮 critic` / `BLOCKER` 等字面量 ⇒ 过程日志检查必须锚定到 **heading 行**，自由文本匹配会误伤形态契约类 ADR。
- **零文件静默通过**：`_iter_adr_files` 在 adr_dir 缺失 / glob 不匹配时直接 return ⇒ 检查会假绿。本轮显式报告「scanned 0 files」。
- **`ARCH_ADR_LINE_LIMIT` 与 `ARCH_FILE_SIZE_LIMIT` 同名不同命**（后者在 `_check_file_size` 也默认 300）⇒ 本轮只动前者，docstring 注明区分。
- **fixture 债**：`_WELL_FORMED_ADR` 备选表只有 2 数据行 ⇒ 新规则一落地该 fixture 自己先红 ⇒ 同步补到 3 行（模板要求 ≥3，fixture 原先欠规格）。
- **`--strict` 死参数**：现状「有发现即 exit 1」使 `--strict` 无作用 ⇒ 本轮修为「默认 exit 0、`--strict` 才 exit 1」（与 warning 级 + opt-in 一致）。
- **ADR-0060 证据保鲜**：该 ADR 的 V-1..V-8 验证的是已合入实现；本轮改动命中其失效条件 ⇒ 修订时必须重跑并更新（Phase 3）。
- **`owns` 语义未裁定**：`skill-role-model/spec.md:70` 把 cross-skill arbitration 列为 out of scope ⇒ 本轮按「owns 只列本 skill 生成的工件」这一既有读法执行，不扩权。
