# quick-fix-proposal-scope-numbered-items

> **Generated by rdd-quick scaffold_plan.sh** — 实际执行时范围扩大了两次，每次都由**已合并的 spec** 或
> **实测语料**推动，不是「顺手改」。三段分别说明。

**Goal**: `generate_full_proposal.py::_extract_scope_items` 与已合并的 capability spec
`openspec/specs/generator-scope-extraction/spec.md` 不符 —— 该 spec 的 5 条 Requirement 里有 2 条
代码从没实现过（`generate-proposal-supports-numbered-scope-items`、
`generate-proposal-numbered-item-subitems-attached`），另有一处 header 拼写漏认导致 Out of Scope 整体丢失。

后果是**用户可见的**：P0 用 `generate_full_proposal.py` 生成的 `proposal.md` 里，`## What Changes`
的 In Scope 会被整个 `## 范围` 段顶掉，Out of Scope 的条目被输出两遍（上一次 change 立项时就手工修过一次，
记录在 `.rddf/improvements/fix-script-project-root-anchoring.md` 的「本次不做」第 4 条）。

**Architecture**: 只改 `_extract_scope_items` 一个函数：

1. **条目识别** 从 `stripped.startswith("- ")` 扩成 `_SCOPE_ITEM_RE = ^(?:-\s+|\d+[.)]\s+)(.*)$`
   —— 编号列表（`1.` `2.` `1)`）是 `.rddf/improvements` 的主流写法。
2. **子项归并**：引入「每个 header 之后第一个条目的缩进」作为 `base_indent`；
   `indent <= base_indent` ⇒ 同级新条目，`indent > base_indent` ⇒ 并入上一条（保留原始缩进）。
   这条规则同时覆盖两种真实形态：`1. item` + `   - sub`（子项）与
   `- **In Scope**:` + `  - child`（孩子才是条目）。**不用**「只要是缩进就算子项」——实测那样会让
   195/291 个 improvement 塌成 1 条。
3. **header 归一化**：`_SCOPE_HEADER_RE = ^[\s#*\-]*((?:out\s+of|out|in)\s+scope)[\s*:：]*$`
   —— 同时认 `**In Scope**:` / `- **Out Scope**:` / `### In Scope` / `### Out of Scope` / `## Out Scope`。
   只认 `Out of Scope` 时，`- **Out Scope**:`（多数文件的写法）不被识别 ⇒ 全部条目境界成 in-scope
   （实测 175 个文件 `out=0`）。

其余逻辑（续行并入、markdown 表格并入、`flush()` 时机、fallback 分支）**一律不动**。

**Tech Stack**: Python 3.12、`re`、pytest。
