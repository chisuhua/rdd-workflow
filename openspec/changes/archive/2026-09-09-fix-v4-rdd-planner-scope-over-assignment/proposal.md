# fix-v4-rdd-planner-scope-over-assignment

> Per 2026-09-09 Oracle 架构审查（`ses_f7a9e01dbffe2Lqu8jYjg4YvL2`，20m deep review）。
> v4 stage-merge (ADR-0043/0044) collapsed `guide-design/plan/ship` into `rdd-builder` 6-phase internal state machine, but left rdd-planner SKILL.md carrying design-era "authoring" responsibility and a phantom "approve proposal creation" HIL. Three contradictions surface:
> 1. spec §3.2 row 165 says planner owns `proposal.md (authoring only, no checkbox)` — but `planner_cmd.py` has zero authoring subcommands and `planner_stage_exit.sh` requires `openspec/changes/<name>` to already exist.
> 2. ADR-0025's `generate_full_proposal.py` (5-段 → full proposal.md converter) was destroyed with guide-design (Wave 3 commit `1095cec`) and never ported — v4 has **no one** authoring proposal.md content.
> 3. §9 demo shows `rddf planner accept ... scaffold tasks.md` while §3.4 Phase 1 + planner not_owns L47 explicitly assign tasks.md to builder.
>
> Verdict B (per Oracle review): revise the architecture. Maintainer's model (planner = metadata/index orchestrator only, communicating via handoff + feedback) is correct; rdd-builder P0 approve owns proposal.md authoring per ADR-0025 D1/D2; complexity triage stays in rdd-quick (not planner-as-authority).

## Why

v4 architecture merge (D2b, 2026-09-04, per ADR-0043) collapsed the 5-stage `arch → design → plan → ship → verify` into 4 stages (`rdd-arch → rdd-planner → rdd-builder → rdd-verifier`) plus `rdd-quick` bypass (ADR-0047). The merge moved the approval gate and D3 spec-delta generation into `rdd-builder` Phase 0 (per spec §3.5.1 row "approve_proposal.sh::generate_spec_delta is invoked from builder Phase 0 approve" + §8 H5), but **left rdd-planner's row in spec §3.2 carrying design-era (ADR-0025) "authoring" responsibility without any corresponding code path**.

A 2026-09-09 Oracle architectural review (session `ses_f7a9e01dbffe2Lqu8jYjg4YvL2`, 20m deep review across 18 documents) confirmed 4 facts + 1 judgment:

**Fact 1 — §3.2 row 165 is paper-only design, zero code implementation.**
- `planner_cmd.py` has zero authoring subcommands (only status/sync/attach/diff/advance-sprint/history/audit/feedback); the §9 demo's `rddf planner new/brainstorm/accept` commands do not exist (cross-checked against §5.1 CLI surface).
- `planner_stage_entry.sh` and `planner_stage_exit.sh` both require `openspec/changes/<name>` to already exist (`if [ ! -d "openspec/changes/$CHANGE_NAME" ]; then exit 2`), presupposing the change is created elsewhere — handoff scripts themselves assume planner doesn't author.
- `proposals_authored` field in `.planner-handoff.json` schema v1 is a fiction: it's derived by `rddf roadmap list | grep -oE 'add-[a-z0-9-]+'`, not from any authoring action.

**Fact 2 — ADR-0025's authoring pipeline was destroyed in Wave 3 and never ported.**
- `skills/guide-design/` was hard-removed in commit `1095cec` (per ADR-0044).
- `generate_full_proposal.py` (5-段 → full proposal.md converter per ADR-0025 D1/D2) vanished with guide-design — `grep -r generate_full_proposal` returns zero hits across the repo.
- `skills/rdd-arch/scripts/approve_proposal.sh` is a **broken shim** pointing to the deleted `guide-design/scripts/approve_proposal.sh` path.
- `skills/rdd-builder/scripts/phase0_approval.sh`'s D3 spec-delta is a **placeholder stub** — writes `"Auto-generated by rdd-builder Phase 0 approve (per ADR-0025 D3)"` as a fake Requirement, not the D1/D2 conversion.

**Fact 3 — §9 demo internally contradicts §3.2/§3.4.**
- §9 line 918: `rddf planner accept demo-change` → "✓ tasks.md scaffolded (no checkboxes yet)"
- §3.2 row 166: builder owns `tasks.md`; §3.4 Phase 1 line 224: "write: openspec/changes/<name>/tasks.md (NEW builder responsibility per user D)"; planner SKILL.md not_owns L47: `openspec/changes/<name>/{design,tasks}.md`.
- Same spec says planner not_owns tasks.md AND demos planner scaffolding tasks.md — unreconcilable.

**Fact 4 — ADR-0038 conflicts with v4 promotion.**
- ADR-0038 §Decision 1: "Implement `rdd-planner` as a **horizontal orchestrator** (NOT a sixth phase)".
- v4 spec §3.3 promotes planner to full stage (per ADR-0042/0043).
- Spec frontmatter claims "Extends (additive, no conflict)" — false; both directly contradict.

**Judgment** — not a deliberate design, but a **shoddy D2b redistribution residue**:
- Intent on paper: planner takes over proposal lifecycle from guide-design (per ADR-0025 migration).
- Implementation: builder P0 owns approval + D3 spec-delta (per §3.5.1/§8 H5); planner has no mechanism.
- Net effect: v4's proposal.md is whatever `openspec new change` scaffolds — a skeleton, not full 5-段-converted content.

**Why this matters**:
- New users reading spec §3.2 will think planner authors proposal.md → the agent mistake I made earlier this session (running `phase0_approval.sh --auto-approve` and labeling it "planner-approve" in commits). This is a load-bearing footgun.
- Three document voices contradict each other (spec / SKILL.md / README): README says `propose` + `add-improve` are "被 rdd-builder 调用" sub-skills; spec/SKILL.md say planner owns authoring entry; propose/SKILL.md L23 self-describes as "被 guide-plan 调用" (stale, guide-plan deleted in Wave 3).
- Builder P1 (line 2425-2427 of plan `v4-stage-merge-wave1.md`) checks `openspec/changes/<name>/proposal.md` exists before running plan-quality gate. If a new change skips full pipeline, proposal.md is a skeleton → verifier gets no real Acceptance content.
- Oracle escalates: "**先做 B1（移植 `generate_full_proposal.py`），再改文档**" — otherwise doc changes will lead code again.

### Out of Scope

- **Complexity triage in planner as authority**: explicitly rejected by Oracle. rdd-quick SKILL.md §P1 self-triages (ADR-0047 D3 "no hard threshold, AI judgment"); planner has weaker signal set (improvement 5-段 + priority + phase) than rdd-quick (plan + TDD steps + AC + code proximity); priority ≠ complexity. Accepted only as **advisory** (recommended_route field, not enforced routing).
- **ADR-0025 D4 content-review 4-layer split**: kept as-is (builder P0 approve absorbs; future refactor if quality issues surface empirically).
- **ADR-0043 stage-merge rollback**: not proposed; only rdd-planner scope correction.
- **Unified rdd-quick + rdd-builder entry**: current `skill_use("rdd-quick")` self-entry + rdd-quick self-triage is correct design; not integrated.
