## Why

- **当前 3 个任务状态源**（互不一致）：
  1. `openspec/changes/archive/<date>-<change>/tasks.md` — 静态历史文件，archive 后永不更新
  2. `.rddf/state/iteration.json` 中可写的 `tasks_done` 字段
  3. `openspec instructions apply --change <name>` 通过 CLI 读取的版本（与 (1) 同源）
- **ADR-0017**: iteration.json 是核心状态；tasks.md 在 archive 后变成历史，不应继续承担"任务完成度"的语义
- **`archive-cleanup-plan-files.md`** (P1, 已存在) 处理 `.rddf/plans/<change>.md` 在 archive 后被立即删除的清理问题；本提案是它的镜像版本（tasks.md 路径治理）
- **本提案范围**：把 archive 后的 tasks.md 统一移动到 `openspec/changes/archive/<date>-<change>/tasks.md`（已经在那儿）— **不删除** — 但 iteration.json 中的 `tasks_done` 派生自 tasks.md 的 `[x]` 计数，并提供 sidecar 模式避免 readers 误读 archive tasks.md

### 本仓库实际复现 (2026-08-05 UsrLinuxEmu session 已验证)

5 个 change 的 archive tasks.md 与 iteration.json tasks_done 对比：

| change | archive tasks.md | iteration.json tasks_done | 真实代码状态 |
|---|---|---|---|
| `removal-graph` | 15/15 [x] | 15/15 | ✅ ship |
| `removal-hardware-puller-emu` | 25/25 [x] | 25/25 | ✅ ship |
| `removal-stream-capture` | 18/18 [x] | 18/18 | ✅ ship |
| `removal-gpu-queue-emu` | 0/23 [ ] | 0/23 | ✅ ship |
| `removal-mem-pool` | 0/18 [ ] | 0/18 | ✅ ship |

**问题**：
- `rddf status` 显示 "archived 0/23" "archived 0/18"——逻辑上自相矛盾（archived 状态不该还有 0 任务待办）
- 用户看到后会以为"这两个 change 没做完就要归档了"，但实际是 ship 流程跳过了 tasks.md 标记步骤

## What Changes

- **In Scope**:
  - 在 `archive.sh::archive_change()` / `archive_on_main.sh` 末尾增加 **tasks.md sidecar 生成**：在 archive 目录中创建 `tasks.md.archived-snapshot`（原 `tasks.md` 的 read-only 副本），并把原 `tasks.md` 替换为一份"archived skeleton"（所有 task 加 `[archived]` 标签 + 真实完成度注释），例如：
    ```
    # Tasks: <change-name> [ARCHIVED 2026-08-04]
    # Source: tasks.md.archived-snapshot (read-only)
    # This change shipped via commit f1070ec. Tasks below marked complete reflect
    # the shipped implementation; for the original author-time estimates see
    # tasks.md.archived-snapshot.
    - [x] 1.1 ...
    - [x] 1.2 ...
    ```
  - `iteration.json` 中 `tasks_done` 由 archive 时的 sidecar `[x]` 计数自动派生（不再手工写 0）
  - `rddf status --iteration` 渲染 archive 后 change 时，显示格式从 `0/23` 改为 `[archived-snapshot 23/23]` 或类似明确标注
  - 单元测试：sidecar 生成 / tasks_done 派生 / status 渲染格式
- **Out Scope**:
  - 不删除 archive 目录中的 `tasks.md`（历史快照保留 7 天后由独立清理任务删除 — `archive-cleanup-plan-files.md` 已有先例）
  - 不修改 `openspec instructions apply --change <name>` CLI 行为（仍读 archive tasks.md）
  - 不修改 tasks.md 在 proposal / plan 阶段的格式

## Impact

- MUST sidecar 文件名固定为 `tasks.md.archived-snapshot`（不变），便于脚本探测
- MUST 把"archived skeleton"模板作为 `archive.sh` 中的常量字符串（不允许散落多份）
- MUST NOT 在 archive 失败时生成 sidecar（sidecar 只在 archive 成功后写）
- SHOULD 让 `rddf status` 输出对 archived change 的 tasks 字段做特殊格式化（参考现有 emoji set）
