## Context

- **当前 3 个任务状态源**（互不一致）：
  1. `openspec/changes/archive/<date>-<change>/tasks.md` — 静态历史文件，archive 后永不更新
  2. `.rddf/state/iteration.json` 中可写的 `tasks_done` 字段
  3. `openspec instructions apply --change <name>` 通过 CLI 读取的版本（与 (1) 同源）
- **ADR-0017**: iteration.json 是核心状态；tasks.md 在 archive 后变成历史，不应继续承担"任务完成度"的语义
- **`archive-cleanup-plan-files.md`** (P1, 已存在) 处理 `.rddf/plans/<change>.md` 在 archive 后被立即删除的清理问题；本提案是它的镜像版本（tasks.md 路径治理）
- **本提案范围**：把 archive 后的 tasks.md 统一移动到 `openspec/changes/archive/<date>-<change>/tasks.md`（已经在那儿）— **不删除** — 但 iteration.json 中的 `tasks_done` 派生自 tasks.md 的 `[x]` 计数，并提供 sidecar 模式避免 readers 误读 archive tasks.md

**问题**：
- `rddf status` 显示 "archived 0/23" "archived 0/18"——逻辑上自相矛盾（archived 状态不该还有 0 任务待办）
- 用户看到后会以为"这两个 change 没做完就要归档了"，但实际是 ship 流程跳过了 tasks.md 标记步骤

## Approach

**Scenarios** (from improvements):

- GIVEN `archive_change(name)` 完成，WHEN 进入末尾，THEN 在 `openspec/changes/archive/<date>-<name>/` 写入 `tasks.md.archived-snapshot`（原内容 read-only）+ 替换 `tasks.md` 为 archived skeleton；iteration.json `tasks_done` 自动从 sidecar 派生为真实完成度
- GIVEN 用户运行 `rddf status --iteration`，WHEN 渲染 archived change，THEN tasks 列显示 `archived (snapshot 23/23)` 或 `[A] 23/23` 等明确标注，避免"archived 0/total"歧义
- GIVEN archived change 的 sidecar 存在，WHEN `openspec instructions apply --change <name>` 被调用，THEN 行为不变（仍读 `tasks.md`，但 `tasks.md` 已被替换为 archived skeleton，仍可被 CLI 解析）
- GIVEN 同一 archive 动作被重入执行，WHEN sidecar 已存在，THEN 跳过生成（幂等）；原 `tasks.md` 已被替换，再次 archive 不会损坏 sidecar

## Implementation Notes

**Constraints** (MUST / MUST NOT / SHOULD):

- MUST sidecar 文件名固定为 `tasks.md.archived-snapshot`（不变），便于脚本探测
- MUST 把"archived skeleton"模板作为 `archive.sh` 中的常量字符串（不允许散落多份）
- MUST NOT 在 archive 失败时生成 sidecar（sidecar 只在 archive 成功后写）
- SHOULD 让 `rddf status` 输出对 archived change 的 tasks 字段做特殊格式化（参考现有 emoji set）
