- **`fix-rddf-status-corrupt-message.md`** (P1, 2026-08-05) 解决了"corrupt 被误报为 not found"的 CLI 消息问题，但**没有解决 AI 写错字段时如何避免触发 corrupt 备份**
- **本提案范围**：fail-closed 策略本身正确（拒绝未知字段），但需要补 (a) 显式错误反馈 + (b) AI 写前预检 + (c) 合法字段白名单文档

**触发链**：
1. AI 写入 `archive_commit` / `feat_commit` / `tasks_note` 三个额外字段

## Goals / Non-Goals

**Goals:**
- `skills/_lib/cli/status_cmd.py`：在 `_mode_a` / `_mode_b` / `feature_cli` 三处**显式打印** schema 校验失败原因（`jsonschema.ValidationError.message` + 字段路径），不再折叠为 "not found"
- 新增 `rddf iteration lint <path>` 命令：read-only 校验，不写备份，只输出哪些字段被禁止、哪些缺失

- `skills/_lib/iteration/store.py::_backup_corrupt_file()` 失败时返回非零退出码 + 把原错误信息写入 `.corrupt.<ts>.reason.txt`（同一 ts）

## Approach

**Scenarios** (from improvements):

- GIVEN iteration.json 含有 schema 不允许的字段（如 `archive_commit`），WHEN `rddf status --iteration` 运行，THEN stderr 显式打印 `"ValidationError: Additional properties are not allowed ('archive_commit' was unexpected) at path: ['changes', 9]"`，并打印 `Allowed fields: name, status, phase, ...`
- GIVEN iteration.json 含 schema-invalid 字段，WHEN `rddf iteration lint .` 运行，THEN 退出码非零，stdout 列出全部非法字段及合法字段白名单；不写 `.corrupt` 备份
- GIVEN `store.py::_backup_corrupt_file()` 被调用，WHEN 备份完成，THEN `iteration.corrupt.<ts>.reason.txt` 与 `.corrupt.<ts>` 文件并存，AI / 用户能精确诊断
- GIVEN AI 调用 `rddf iteration allowed-fields`，WHEN 返回字段白名单，THEN AI 写入前可对照（推荐路径：`rddf iteration allowed-fields >> allowed.txt`）

## Implementation Notes

**Constraints** (MUST / MUST NOT / SHOULD):

- MUST 沿用 `jsonschema.Draft7Validator`（项目已有依赖）
- MUST NOT 修改 `additionalProperties: false` 策略（fail-closed 是设计选择）
- MUST 把 lint / allowed-fields 暴露为 rddf 子命令，而非只有 Python API
- SHOULD 在 `rddf status` 输出末尾增加一行 `Hint: run 'rddf iteration lint' to diagnose`，方便用户自检
