# Spec Delta: v4-planner-scope-correction

## ADDED Requirements

### Requirement: planner-no-openspec-authoring

The `rdd-planner` skill MUST NOT own `openspec/changes/<name>/proposal.md`. `spec/superpowers/specs/2026-09-04-rdd-workflow-v4-architecture-stage-merge.md` §3.2 row 165 MUST NOT contain `proposal.md (authoring only, no checkbox)` in the planner's `Files owned` column.

#### Scenario: spec §3.2 row 165 has no proposal.md authoring reference

GIVEN a maintainer audits `docs/superpowers/specs/2026-09-04-rdd-workflow-v4-architecture-stage-merge.md`
WHEN they grep for `proposal.md (authoring only` in row 165
THEN zero matches are returned (only builder row 166 may mention proposal.md authoring)

#### Scenario: rdd-planner SKILL.md role.owns excludes proposal.md

GIVEN the `skills/rdd-planner/SKILL.md` frontmatter `role.boundaries.owns` field
WHEN parsed by the role boundary check
THEN `openspec/changes/<name>/proposal.md` does NOT appear in `owns`
AND it DOES appear in `not_owns`

### Requirement: builder-p0-approves-proposal-authoring

`rdd-builder` Phase 0 4-option approval gate MUST own the proposal.md authoring pipeline (per ADR-0025 D1/D2 "生成 → 确认 → 落盘"). `phase0_approval.sh` approve branch MUST invoke `generate_full_proposal.py` (restored from commit `1095cec^`) to produce a non-skeleton proposal.md from the linked `.rddf/improvements/<name>.md` 5-段 content.

#### Scenario: phase0_approval.sh --auto-approve produces full proposal.md

GIVEN a `.rddf/improvements/fix-v4-rdd-planner-scope-over-assignment.md` exists with full 5-段 + AC
WHEN `bash skills/rdd-builder/scripts/phase0_approval.sh fix-v4-rdd-planner-scope-over-assignment --auto-approve` runs
THEN `openspec/changes/fix-v4-rdd-planner-scope-over-assignment/proposal.md` contains:
  - `## Why` populated from `## Why` of improvement (≥3 paragraphs)
  - `## What Changes` populated from `## 范围` of improvement (≥3 items)
  - `## Acceptance` populated from `## 验收标准` of improvement (≥3 checkboxes)
AND no `<skeleton motivation>` or `TBD` placeholder text remains

#### Scenario: D3 spec-delta is generated alongside proposal.md

GIVEN phase0_approval.sh --auto-approve completes successfully
WHEN the user inspects `openspec/changes/<change>/specs/<name>/spec.md`
THEN it contains ≥3 `## ADDED Requirements` blocks with proper `### Requirement:` + `#### Scenario:` structure
AND no `Auto-generated by rdd-builder Phase 0 approve` placeholder text

### Requirement: planner-handoff-schema-field-renamed

`.planner-handoff.json` schema v1 field `proposals_authored` MUST be renamed to `proposals_ready` to eliminate the fiction of "authoring" (planner never authors; field is derived from attached improvements). `_lib/schemas/planner_handoff_schema.json` MUST reflect this rename.

#### Scenario: schema v1 properties block excludes proposals_authored

GIVEN a maintainer parses `_lib/schemas/planner_handoff_schema.json`
WHEN they read the `properties` block
THEN `proposals_authored` is NOT a defined property
AND `proposals_ready` IS defined with description "attached for builder, not authoring product"

#### Scenario: planner_stage_*.sh scripts emit proposals_ready

GIVEN `planner_stage_exit.sh` runs for change X
WHEN it writes `.planner-handoff.json`
THEN the output JSON contains `proposals_ready: [...]` (not `proposals_authored`)
AND the count matches attached improvements in `.rddf/improvements/`
